# Litly

> **Keep this file current.** Whenever product direction, features, architecture, limits, domains or deploy steps change, update this doc in the same change, without waiting to be asked. Remove anything that's no longer true.

Live at **https://litly.com**. A "what kept you up last night?" feed. Anyone can read it, but you must be signed in (Google or Apple) to post, reply or attach a photo. Posts show under a random pseudonymous username and avatar, never a real name. The public feed starts fresh for everyone at the same moment every day, but nothing is deleted by the reset: posts stay on their author's profile and at their `/p/<id>` link until the author deletes them.

## What users can do
- **Post** (signed in only) up to 500 characters, optionally with one photo. Posts and replies show the author's profile username (linking to `/u/<username>`) and avatar.
- **Photos:** the attach button in the composer picks an image; the browser shrinks it to at most 1600px, re-encodes it as WebP (JPEG on Safari), which also strips EXIF/location, then uploads it with the post as multipart form data. The Worker checks the real file type from its magic bytes (JPEG/PNG/WebP, max 3MB), stores it in the R2 bucket `litly-media` (binding `MEDIA`, key `img/<uuid>.<ext>`) and serves it at `/img/<key>` with a one-year immutable cache. Deleting the post deletes the photo. In the feed and on profiles the photo is cropped to a full-width frame between 6:5 and 2:1 (max 300px tall, biased toward the top, `.fpost .pimg`) so tall screenshots, panoramas and square photos all take about the same space; the post page shows it whole. Posts only, not replies.
- **Profile (`/u/<username>`, `public/profile.html`):** public page with the avatar, username, join date and tabs for every post and every reply the person has made (replies link to the reply in its thread). The owner sees delete buttons and an "Edit profile" button to `/account`. The header's profile chip links here. Data comes from `GET /api/user?name=` (one D1 batch). To load smoothly it paints the last copy from `sessionStorage` (`litly_u:<name>`) or a header placeholder first, then refreshes; the signed-in check runs in parallel.
- **Delete:** authors can delete their own post (also removes its replies, hearts and photo) or reply (`POST /api/post/delete`, `/api/reply/delete`). A reply that has answers under it stays as a "[deleted]" placeholder (`deleted = 1`, text and author cleared) like Reddit; otherwise it is removed.
- **Heart** a post. One per person per post, and tapping again undoes it. (Stored in the `metoos` table and `/api/metoo`, a leftover name.)
- **Post page (`/p/<id>`, `public/post.html`):** Each feed post shows pills (heart, comment count, share). Comment (or tapping the post) opens the post page: the same site header as the feed (logo left, Log in / profile right, from `public/nav.css` and `public/nav.js`, shared by every page so they never move), a Back button below it, the post, a reply box and the reply tree. `GET /api/post?id=` returns the post plus all its replies flat; the browser nests them by `parent_id`.
- **Reply** to a post or to another reply, up to 280 characters, nested Reddit-style: avatar header with the text aligned under the name, children indented one avatar width, a thread line from the parent's avatar with a curved elbow into each child, tap the line or the circled minus to collapse (the avatar becomes a circled plus beside just the name and time), siblings sorted by hearts then oldest, an "OP" badge on the original poster's replies (same account as the post), and past depth 7 (4 on phones) a "Continue this thread" link that opens that reply as the pinned view. Replies can be hearted (`reply_metoos`, via `/api/metoo` with `reply: true`), replied to inline, and shared.
- **Share** copies the link (native share sheet on touch devices). A reply link is `/p/<postId>?r=<replyId>`: the post page pins that reply (with its own replies) in a highlighted "Shared reply" block above the full thread. Links keep working until the author deletes the post (then it shows a "This one's gone" page); `/p/` is `Disallow`ed in robots.txt and `noindex`. No OG image for shared posts or replies yet.

## How it works
- **Hosting:** One Cloudflare Worker (`src/worker.js`) serves both the API and the static page in `public/`.
- **Database:** Cloudflare D1, which is SQLite (`schema.sql`). Tables: `posts`, `replies` (with `parent_id` for nesting), `metoos` (post hearts), `reply_metoos` (reply hearts), `bans`, `profiles`, `visitor_days`, `visitor_stats`, `countries`, `recent_visits`, plus Better Auth's `user`, `session`, `account`, `verification`. There's also an unused `subscribers` table from an old email waitlist.
- **Daily reset:** Every day at **04:00 UTC**, set by `RESET_HOUR_UTC` in the worker (midnight US Eastern during daylight time), the feed (`GET /api/posts`, the sign-up teaser `/api/top`) starts over: it only lists posts from the current 24h cycle. Nothing is purged: there is no cron, and old posts, replies and photos stay until their author (or an admin) deletes them. The countdown uses the server's clock and shows the reset time in each visitor's own time zone.
- **Identity and privacy:** Posting needs a session (Better Auth). `posts.user_id` and `replies.user_id` point at the account, and the public author name/avatar are joined in from `profiles` at read time (so changing your username or avatar on `/account` updates everything you've posted). Real names and emails are never shown. The server also stores a salted hash of the IP (`SALT` secret), never the raw IP, for bans and me-too dedupe. A reply shows an "OP" badge only when the post's own account wrote it (same `user_id`).
- **Avatars:** DiceBear 10 "Shadows" (CC0 silhouettes, `src/avatars.js`, packages `@dicebear/core` and `@dicebear/styles`), bundled into `public/avatars.js` by esbuild. Colors come in 24 matched [background, ink] pairs (light, mid-tone and dark backgrounds) picked from the seed, so contrast is guaranteed. The seed is the avatar string stored on the person's profile (random on first visit). There's a small shuffle button on their avatar on `/account` (random new avatar, applied on Save).
- **Spam and abuse filters in `looksBad()`:** Blocks links, bare domains, emails, phone numbers, @usernames, scam and "contact me" words (Telegram, crypto, Snapchat and similar), and all-caps text.
- **Other limits:**
  - **Rate limits:** 3 posts and 10 replies per hour per account.
  - **Duplicates:** Exact duplicate posts or replies are rejected.
  - **Honeypot:** A hidden `website` field catches bots.
- **Moderation:** `/admin` (`public/admin.html`) lists posts and replies and can delete, restore or ban. The API is protected by the `ADMIN_TOKEN` secret, sent as `Authorization: Bearer <token>`. Banning deletes all of that person's content.
- **Visitor bar (`public/visitors.js`, loaded by `nav.js` on every page):** a thin bar under the header, "N awake · T visits recently" (the number is really the all-time total) plus the 5 most recent distinct country flags; tapping it opens a `<dialog>` listing the latest 200 first-time visits ("Visitor in Belgium", relative time, new ones slide in). **Awake = loaded or touched the site in the last 15 minutes** (`AWAKE_MS`), even if they've left. Country is `request.cf.country` (no IP lookup; Tor/unknown = `XX`, shown with `/globe.svg`). The browser keeps a random id in `localStorage` (`litly_vid`) that changes every UTC day and POSTs it to `/api/visit` on load, when the tab becomes visible, every 30s while visible and after interaction; the Worker stores only SHA-256(day + id) in `visitor_days` (dedupe + `last_seen`), and on a hash's first sighting of the day bumps `visitor_stats` (daily + `total`), `countries` and the rolling `recent_visits` log (trimmed to 200). Bots are skipped by user agent. `GET /api/visitors` returns the snapshot. It polls instead of using WebSockets/Durable Objects, since "awake" is a 15-minute window. Flags are `circle-flags` (MIT, `public/flags/*.svg`, license in `public/flags/LICENSE.txt`); names come from `Intl.DisplayNames`.
- **Domains:** All non-canonical hosts (`www.litly.com` and `*.workers.dev`; the old `redirect-worker/` is no longer needed) 301 redirect to `litly.com`.

- **Sign-up page (`/signup`, `public/signup.html`):** Headline "Can't sleep? Vent about it." (accent on the second line). Google and Apple buttons (Better Auth, `src/auth.js`, served under `/api/auth/*`) with terms and privacy agreement text placed directly underneath. The right side shows the sleepy mascot plus a slow single horizontal carousel of cards (fixed 340px wide, fading at the edges, drifting left in a seamless loop, pausing on hover) built from the top 5 posts by me-too from `GET /api/top` (bodies trimmed to 180 chars; the cards reuse the feed's look: avatar, name and time, text, and the heart/comment/share row; no countdown on this page), so the full feed isn't exposed to logged-out visitors. Signed-in users are not redirected away, so they can sign in with a different account. On mobile (<=860px) the right side is hidden and the headline and buttons are centered.

- **Legal pages:** `/privacy` (`public/privacy.html`) and `/terms` (`public/terms.html`), linked from the sign-up page and the footer. They contain a `[CONTACT EMAIL]` placeholder to replace with a real address, and they should be reviewed by a lawyer.

- **Accounts:** Sign in with Google or Apple via Better Auth. Real name and email come from the OAuth provider and are stored in the `user` table; they're never shown anywhere in the UI (not even on `/account`) and `/api/profile` doesn't return them. The header shows a "Log in" button, or the person's avatar + username (links to their profile) when signed in. To avoid flicker, `public/nav.js` paints the header from a `litly_me` localStorage cache before first paint, then `/api/profile` confirms it (`window.litlyMe` is that promise, shared by pages); a `litly_pending` flag hides the header while returning from a sign-in. Sessions last 90 days of inactivity (rolling, refreshed daily). `/account` (`public/account.html`) shows the avatar (with shuffle button) and username; `GET/POST /api/profile` assigns a random username (e.g. `hazy_moon_838`) and avatar on first visit, and lets them change both (username 3-20 chars `[a-z0-9_]`, unique). The page paints from the `litly_me` cache and reuses nav.js's single `/api/profile` request (`window.litlyMe`) instead of waiting on its own. Session checks use a memoized provider-less Better Auth instance with a 5-minute signed cookie cache (`src/auth.js`), so a sign-out can take up to 5 minutes to reach other devices' cached sessions. When signed out, the composer and reply boxes are read-only and send you to `/signup`.

## Design
Social preview (Open Graph / Twitter card) image is `public/og-v4.png` (1200x630): black, the sleeping mascot centered over "Can't sleep?" with "Vent about it." in the accent color beneath it, and the logo top-left. No subtext, and no og/twitter description tags. Bump the filename when it changes, since platforms cache these.

Apple-style minimalism: black background, system SF Pro font and a soothing periwinkle accent (`#869ad5`) matching the tired avatar mascot. The brand logo (`public/logo.svg`) features a custom tired mascot wrapped in a blanket in place of the letter "I" (Pixar-style). Favicon suite follows modern web standards: scalable `public/favicon.svg` and multi-resolution 32-bit `public/favicon.ico` (16, 32, 48px) with full alpha transparency, featuring the blanket-wrapped mascot inside an Apple-style rounded black squircle with transparent corners; alongside `public/apple-touch-icon.png` (180x180) and standard PNG icons (`favicon-32x32.png`, `favicon-16x16.png`). **Home layout (>=1180px):** three columns, with the composer and feed starting right under the header in the middle, a globe on the left and the hero (sleeping character, headline, countdown) on the right; both side panels are sticky. Below 1180px the globe is hidden and the hero (sleeping character, headline, countdown) sits above the composer. The globe (`public/globe.js`, plain 2D canvas, drag to spin, pauses offscreen, static with reduced motion) draws land as dots from a 1-degree mask in `public/land.js` (Natural Earth via the `world-atlas` land-50m file), lights up the real night side from the current sun position, and shows real visitor countries from `window.litlyPlaces` (set by `visitors.js` from `/api/visit`'s `places`, positioned with the country centers in `public/centroids.js`, MIT data from gavinr/world-countries-centroids): every country ever seen has a steady glow that grows with all-time visits, and countries with someone awake in the last 15 minutes also pulse, so it never goes dark when the 15 minutes pass. Unknown (`XX`) visitors aren't shown. The hero features an animated sleeping character (`public/sleepless.webp` with `public/sleepless.gif` fallback, preloaded with high fetch priority) that blinks and yawns above the countdown. The home page shows no visible title or subtext (a visually hidden `h1` keeps it accessible), and the mascot and timer stay centered, including on phones. The composer's bottom bar has a (currently disabled, "coming soon") photo/video attach button on the left and Post on the right. The post composer is a compact auto-expanding field featuring a character-by-character typing placeholder cycling punchy late-night thoughts (animating immediately on start). Keep everything else simple, with no decorative noise.

## Develop and deploy
```sh
npm install
npm run dev      # local server at http://localhost:8799 with a local D1 database (needs .dev.vars with ADMIN_TOKEN=...)
npm run deploy   # builds avatars and deploys to production
```
- **Cloudflare account:** "Litly" (`account_id` in `wrangler.toml`, ID `1c19c252143c91371ba40fdad4e6551d`), which holds the Worker `cant-sleep-feed`, the D1 database `cant-sleep` and the `litly.com` zone. The domain is registered at GoDaddy, which only points its nameservers at Cloudflare (`denver.ns.cloudflare.com`, `kallie.ns.cloudflare.com`). DNS keeps the iCloud email records (2 MX, SPF and `apple-domain` TXT, `sig1._domainkey` DKIM, all DNS only): never delete or proxy those. The site moved here from the "Lemelson Capital + Amvona" account in Oct 2026, so that account's old Worker and zone are leftovers to clean up once the move is confirmed.
- **Schema changes:** Run them on production with `npx wrangler d1 execute cant-sleep --remote --command "..."`. `schema.sql` uses `CREATE TABLE IF NOT EXISTS`, so new columns on existing tables need an `ALTER TABLE`.
- **R2 (photos):** bucket `litly-media` (binding `MEDIA`) lives in the Litly account; created with `npx wrangler r2 bucket create litly-media`. Local dev simulates R2 automatically.
- **Secrets:** `SALT`, `ADMIN_TOKEN`, `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_ID/SECRET`, `APPLE_CLIENT_ID/TEAM_ID/KEY_ID/PRIVATE_KEY` are Wrangler secrets on the Worker. `scripts/set-secrets.sh` copies them from `.dev.vars` and the Apple `.p8` key (and `SALT` from the environment, or generates one). Never commit them. `.dev.vars` is gitignored.
